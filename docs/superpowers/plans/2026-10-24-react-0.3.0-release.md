# React 0.3.0 Release Preparation Plan

**Goal:** Prepare the independently versioned React 0.3.0 candidate and complete upgrade instructions without publishing it.
**Architecture:** Keep Core and React's exact Core dependency at published 0.2.0. Consolidate the native DnD and React 19 upgrade guidance into the existing packaged migration guide. Portal delivery follows confirmed npm publication and a reviewed source revision.
**Tech stack:** Bun 1.4.0, Node 24/26, TypeScript 6 emit / 7 checking, native dnd-kit React 0.5.1.
**Spec:** User request to prepare public 0.3.0 with care for breaking changes, 2026-10-24.

## Constraints

- Public-only scope; downstream production adoption is handled separately by its owner.
- No npm staging/publication, tags/Releases, portal ingestion/translation or deployment.
- Preserve runtime implementation, source-quality gates and published Core 0.2.0.
- A prepared version or versioned changelog is not proof of publication.

## Review focus

Cancelled/outside drags must not write; old/native providers must not be mixed; function component refs preserve ordinary JSX but not exotic internals; hosts align Query 5.104.5; Node runtime remains >=24.0.0; install/publication/portal status is explicit.

## Policy review ruling

The shared README policy is being clarified in a separate docs worktree: full
project overviews remain bilingual; compact npm package READMEs are English-only
and do not require five headings or badges. Both package READMEs use the compact
format. No Japanese package README is created or included in the archives.
Core's documentation correction remains Unreleased until its next independent
release; published Core 0.2.0 bytes must not be overwritten.

Bun's workspace lock metadata is checked against each manifest version. Dependency
resolution is unchanged. The existing package archive verifier continues to reject
unexpected README filenames. The README checker is adopted from the shared public
template with an explicit npm format in the existing inventory.

## Verification handoff

Working-tree preflight passed: `bun run verify`, `bun run check:docs`,
`bun run test:consumer`, and `bun run check:react-core --release`. Both published
Core 0.2.0 and candidate Core lanes passed with React 0.3.0. Actual archives contain
only the English `README.md`; consumer checks cover ESM/CommonJS, Node 24.0.0,
TypeScript 6/7 and documented form SSR. Shared README tests pass all 18 cases.
Independent policy/checker and release-documentation reviews have no remaining
findings. Runtime/browser implementation is unchanged from the merged main source;
no new browser certification is claimed for these documentation/version edits.

These are preflight results, not final clean-commit publication evidence. After
review/merge, select the exact main commit and its successful Source quality run,
retain the release workflow's verified immutable archive and obtain publication
authorization through the existing process. No tag, Release, npm staging or portal
publication has been performed. Core remains 0.2.0; its README correction awaits a
future independently selected Core release.

Shared policy changes are isolated on `docs/npm-readme-policy` in the docs owning
repository. They affect governance and maintainer validation, so require no npm
package release. Policy-site deployment is a separate delivery step.
